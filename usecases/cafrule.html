🧩 Fehlerhafte CAF Rule/ Reason ID

Praxisfall zur Analyse einer fehlerhaften Steuerungslogik.

📖 Situation

Ein UMSA-Fall wird grundsätzlich korrekt verarbeitet.  

Trotzdem fällt auf:  
  • falsche Kommunikation
  • unerwartete Reports
  • falsche Zuordnung
  Die Ursache liegt in einer fehlerhaften Reason ID oder CAF Rule.

❓ Aufgabe

Du übernimmst die Analyse des Falls. Finde heraus:  

  • Wo wurde der neue Termin erfasst?
  • Wo wurde der neue Termin erfasst?
  • Welche Kundenwirkung entsteht
  • Wer informiert werden muss

🔍 Leitfragen

  • Welcher Termin war ursprünglich geplant?
  • Welcher Termin ist neu gültig?
  • Welche Systeme müssen aktualisiert werden?
  • Welche Kommunikation muss angepasst werden?
  • Wer ist der verantwortliche Owner?

✅ Lösungsweg

1. NOVIS prüfen

  • Maintenance Ticket
  • Terminänderung
  • Reason ID

2. NC-CIA prüfen

  • Kundenkommunikation
  • Reminder
  • Avisierung

3. SEO prüfen

  • Plan-Werte
  • Ist-Werte
  • Events

4. Kundenwirkung beurteilen

  • Neue Kundeninformation notwendig?
  • Reminder neu planen?

📚 Lessons Learned

Eine Terminverschiebung betrifft nie nur ein System. Wichtig sind:  

  • konsistente Daten
  • identische Termine
  • korrekte Kundenkommunikation
Die Qualität einer Terminverschiebung zeigt sich daran, dass kein Kunde widersprüchliche Informationen erhält.

🚀 Mini Mission

Nimm einen echten oder fiktiven Fall. Beschreibe:  

  • alter Termin
  • neuer Termin
  • betroffene Systeme
  • Kundenwirkung
  in maximal 5 Minuten.
